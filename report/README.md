# Scientific report — LoRa-enabled remote patient monitoring

IEEE-style conference paper (IEEEtran, **7 pages including references**) describing the project as it actually
stands: what is implemented and tested, what was simulated, what was measured on the bench, and what is still pending.

| File | Content |
|---|---|
| `main.pdf` | compiled report (Tectonic 0.15.0 / XeTeX, 7 pages) |
| `main.tex` | LaTeX source (single file; figures are `\input` from `figures/`) |
| `references.bib` | bibliography (IEEEtran style) |
| `figures/tikz/*.tex` | vector diagrams: system architecture (Fig. 1), v2 frame layout (Fig. 3), UART wiring (Fig. 4) |
| `figures/plots/*.tex` | pgfplots charts that read `figures/data/*.dat` |
| `figures/data/` | every plotted number, regenerated by `tools/make_figure_data.py` |
| `figures/*.png, *.jpg` | photograph, OMNeT++ screenshots, dashboard screenshots |
| `figures/screenshots/` | additional real dashboard screenshots (network twin, AI page, predictions tab) not used in the paper |
| `tools/` | scripts that produced the data and the dashboard screenshots |

## Compile

**Overleaf** — zip the `report/` folder (or use the prepared `RPM_LoRa_report_overleaf.zip` if present), then
*New Project → Upload Project*. The default compiler (pdfLaTeX) works; the document uses only standard TeX Live
packages (IEEEtran, TikZ/pgfplots 1.18, subfig, booktabs, tabularx, hyperref).

**Locally**

```bash
tectonic main.tex
```

```bash
latexmk -pdf main.tex
```

`main.tex` loads `fontenc` T1 so that XeTeX (Tectonic) and pdfLaTeX (Overleaf) use the same Times fonts and give the
same page count. After any edit, check that the PDF is still **at most 7 pages**.

## Dashboard screenshots

Captured from the running platform (`python -m gateway.server`, simulation mode) with headless Microsoft Edge driven
over the DevTools protocol (`tools/capture_dashboard.py`, `tools/capture_detail.py`; viewport 1280×860 CSS px,
device scale factor 2). The scripts log in with the local demo doctor account read from the git-ignored
`data/demo_credentials.txt` (the password is never printed), start a simulation scenario (F for the overview, G for the
patient view), capture the pages and stop the simulation again. All patients shown are synthetic and labelled “(SIM)”.

## Honesty rules applied

* Simulation, bench observation, software tests, analytical estimates and model evaluation are reported separately
  (Table VII of the paper).
* No physiological data from people: all vital-sign values are synthetic or simulated.
* No clinical validation or regulatory compliance is claimed; open items are marked *pending*.
